# 契约治理规则

## 1. 唯一真源

`contracts/v0.2/` 是当前 MVP 的评审契约，`apps/api/app/schemas.py` 是运行时类型源，FastAPI `/openapi.json` 是可执行规范。`contracts/v0.1/` 只保留为历史 Mock，不得继续扩展。

- `openapi.yaml`：HTTP 路径、状态码与请求响应；
- `schemas/`：智能体之间交换的结构化产物；
- `examples/`：并行开发和回归测试使用的固定示例。

代码中的类型可以根据契约生成或手工映射，但不能反过来悄悄改变契约。

## 2. 核心产物链

```text
CaseContext
    → EvidenceBundle
    → RiskAssessment
    → DocumentDraft
```

运行状态统一使用 `AgentRun` 表达。接口错误统一使用 `ErrorResponse`，不能让前端解析任意字符串判断错误类型。

## 3. 字段规则

- 相似度和启发式评分统一使用 `[0, 1]`；
- `null` 表示未执行、未知或证据不足，不能自动等同于 `0`；
- 所有聚合分必须携带配置版本；
- 状态数据必须携带截至日期或数据集版本；
- 证据必须包含来源标识；
- 法律引用必须包含资料标识和片段定位；
- 所有风险和文书产物必须包含人工复核标志。

## 4. 变更流程

1. 提交契约变更说明和业务理由；
2. 同时更新 schema、OpenAPI、Mock 和受影响文档；
3. 运行 `make validate`；
4. 通知四个模块负责人；
5. 向后兼容的新增字段可进入当前小版本；
6. 删除字段、修改类型或改变字段语义必须创建新版本目录。

## 5. Mock 使用规则

Mock 数据是格式正确的教学示例，不是真实商标或法律结论。所有示例编号使用 `DEMO` 或 `demo` 前缀，展示时必须标记为演示数据。

真实端点不提供隐式 Mock 模式。CI 使用假模型、合成数据和依赖替身；离线前端开发可基于 v0.2 示例构造显式测试夹具。

## 6. 合并门槛

- 所有 JSON 可解析；
- 示例满足对应 schema；
- OpenAPI 中引用的本地文件存在；
- 不包含疑似密钥或真实隐私数据；
- 公共字段不存在未说明的语义变化。
