# MarkLens 完整使用说明

> MarkLens 用于商标知识学习、项目内方案整理、近似初筛和报告沉淀。结果仅供学习与辅助决策，不构成法律意见，也不能替代官方检索或专业复核。

## 1. 项目结构

```text
apps/
  web/                 React + Vite 用户端与运营后台
  api/                 FastAPI、Alembic、数据模型和业务服务
contracts/             接口契约与示例
infra/                 MySQL、Nginx、systemd 部署配置
scripts/               初始化、数据和部署脚本
docs/                  使用、报告、答辩与设计文档
```

前端只通过 `/api/v1` 调用后端；MySQL、模型密钥、数据同步和文件存储都在服务端。用户端、运营端和管理员端使用不同角色校验，不能只依靠隐藏菜单判断权限。

## 2. 本地配置与启动

### 前置条件

- Python 3.12、Node.js 22+、pnpm 10+；
- MySQL 8.0+（推荐 MySQL 8.4，`utf8mb4`）；
- macOS 可使用项目的 `make db-up`，也可使用 Docker Compose。

### 初始化

```bash
cp .env.example .env
# 编辑 .env：至少设置 AUTH_SECRET、数据库连接和演示管理员密码
make setup
make db-up                 # 或 make db-up-docker
make db-migrate
make seed
make models-download       # 首次运行多模态检索前执行
```

分别启动两个终端：

```bash
make dev-api               # http://localhost:8000，接口文档 /docs
make dev-web               # http://localhost:5173
```

确定性检索不需要模型密钥。品牌顾问、AI 报告和可选的图样模型复核由用户在网页「AI 设置」中临时填写自己的模型与 API Key；密钥不写入数据库，也不会作为服务器默认配置保存。

### 常用验证命令

```bash
make test-api
make test-web
make build-web
make check                 # 契约、lint、前后端测试与构建
```

## 3. 用户端操作

1. 注册普通用户，进入“我的项目”，新建一个品牌项目并写明业务背景。
2. 点击“添加商标方案”。可以：
   - 点击“选择登记附件”，上传 PDF、DOCX、PNG、JPEG 或 WebP；系统提取名称、用途、类别及可用图样；
   - 或直接手动填写商标名称、尼斯分类、商品/服务描述和图样。
3. 核对自动回填内容后，点击“确认并开始风险初筛”。任务完成后查看候选、图样对照、五维雷达图和分项证据。
4. 在风险页生成并保存报告；报告可以继续编辑和导出 PDF。
5. 回到项目页，使用醒目的“咨询品牌顾问”入口提出具体问题。顾问会结合项目、方案与法律资料给出带引用的回答。

## 4. 运营与管理员操作

- `operator`：访问 `/ops`，维护学习专题、视频、案例题库和已登记的数据源；
- `admin`：在上述能力基础上管理用户角色和审计信息；
- 演示管理员由 `.env` 的 `DEMO_ADMIN_EMAIL` 与 `DEMO_ADMIN_PASSWORD` 初始化。真实密码不得写入 README、代码或 Git。

运营后台仅展示脱敏运行状态，不展示其他用户项目中的商标、图样或报告正文。

## 5. 生产部署（腾讯云示例）

建议使用 4 核 4G 的腾讯云主机。生产环境由 Nginx 在 `80` 端口提供前端静态文件并反向代理后端 `127.0.0.1:8001`；不需要暴露 Vite 开发端口。

### 首次部署

```bash
# 在服务器上完成；示例不含任何账号、密码或 Key
git clone <你的 GitHub 仓库> /opt/marklens
export MARKLENS_MYSQL_ROOT_PASSWORD='<仅在服务器终端设置>'
export MARKLENS_ADMIN_EMAIL='<演示管理员邮箱>'
export MARKLENS_ADMIN_PASSWORD='<强密码>'
sudo -E bash /opt/marklens/scripts/deploy/bootstrap-server.sh

sudo bash /opt/marklens/scripts/deploy/prepare-server.sh
```

`bootstrap-server.sh` 会在服务器本地生成 `DATABASE_URL`、`AUTH_SECRET`、`HEALTH_CHECK_SECRET` 与独立的数据库应用密码，并以 `640 root:marklens` 权限写入 `/opt/marklens/.env`，仅供 root 和 API 服务用户读取。不要在 GitHub、Nginx 配置或 systemd 单元文件中保存这些值。

脚本默认将 `MODEL_RUNTIME_ENABLED=false`，以确保 4G 服务器可先稳定运行 OCR、pHash、确定性文本检索和课程图样梯度。确认模型权重已下载且有足够内存后，再在服务器私有 `.env` 中改为 `true` 并重启 `marklens-api`。

### 更新与检查

```bash
cd /opt/marklens && git pull --ff-only
sudo bash scripts/deploy/prepare-server.sh
systemctl status marklens-api
curl -fsS http://127.0.0.1:8001/health
curl -I http://127.0.0.1/
```

开放安全组/防火墙的 `80`（及配置 HTTPS 后的 `443`）端口。正式答辩前建议绑定域名并使用 Certbot 配置 HTTPS，然后将 `CORS_ORIGINS` 改为实际 `https://` 域名。

## 6. 故障排查

| 现象 | 检查方式 |
| --- | --- |
| 附件上传失败 | `systemctl status marklens-api`；确认 `/opt/marklens/apps/api/data/uploads` 可被 `marklens` 用户写入。 |
| 图样显示占位图 | 确认已登录；前端以带令牌方式读取私有图样，刷新后检查浏览器网络请求。 |
| 初筛在 20% 失败 | 检查图样存储路径和 `journalctl -u marklens-api -n 100`；相对路径已统一解析到 API 服务目录。 |
| 顾问/报告提示需要模型配置 | 进入网页「AI 设置」，填写当前用户自己的模型、接口地址与 API Key 后重试。 |
| 登录失效 | 检查 `AUTH_SECRET` 是否在部署期间被更改，以及 `COOKIE_SECURE` 与 HTTP/HTTPS 是否匹配。 |
