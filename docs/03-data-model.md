# 数据与领域模型

## 1. 数据分层

- **原始层**：仅保存依法、依许可取得的原始记录和来源元数据；
- **规范层**：清洗后的商标、类别、商品/服务、主体和法律资料；
- **派生层**：OCR、拼音、向量、缩略图和规范化字段；
- **运行层**：检索、分析、文书草稿、引用和校验记录；
- **评测层**：脱敏查询、相关性标签、期望引用和错误分类。

原始层和派生索引默认不提交 Git。仓库只允许提交许可明确的最小脱敏样本。

## 2. 核心实体

### `trademark`

| 字段 | 说明 |
|---|---|
| `id` | 内部稳定标识 |
| `application_no` | 申请号，可为空但不得伪造 |
| `name_raw` / `name_normalized` | 原始/规范化文字 |
| `applicant_name` | 申请人名称 |
| `status_code` / `status_as_of` | 状态及其截至日期 |
| `application_date` | 申请日期 |
| `image_asset_id` | 图样文件引用 |
| `source_id` | 来源记录 |
| `source_updated_at` | 来源数据更新时间 |

类别和商品/服务项目是多值关系，应拆为 `trademark_class` 与 `trademark_item`，避免把类别列表塞入单字段。

### `trademark_feature`

保存派生特征：OCR 文本、拼音、文本/图像向量引用、模型标识、模型版本、预处理版本和生成时间。向量可存于专用索引，关系库只保存可追溯引用。

### `legal_source` 与 `legal_chunk`

保存资料类型、标题、发布机关、文号、发布日期、生效/失效日期、规范来源链接、版本和片段定位。案例必须区分裁判文书、指导/典型案例和二次解读，不能混为同等权威。

### `search_run` 与 `search_hit`

`search_run` 记录输入快照和所有版本信息；`search_hit` 保存各召回通道原始分数、排名、重排分、解释码和证据充分度。不要只保存最终总分。

### `risk_analysis`

引用一次检索运行，保存评分配置版本、提示等级、规则命中、解释与人工复核状态。风险等级是系统提示，不是商标法律状态。

### `document_draft`

保存文书类型、模板版本、事实快照、段落内容、引用清单、校验状态和修订版本。模型输出与用户修改应分版本保存。

## 3. 来源与许可清单

任何数据进入索引前，必须登记：

- 来源名称和规范链接；
- 获取方式与获取日期；
- 授权、许可或使用依据；
- 可保存、可展示、可再分发的范围；
- 更新频率和失效策略；
- 字段覆盖率和已知质量问题。

当前尚未指定真实数据源，因此项目文档和样本不得暗示已接入某个官方或商业数据库。

## 4. 数据质量规则

- 空值保持为空，不用模型猜测；
- 状态必须绑定截至日期；
- 来源链接与原始标识至少保留一个；
- 同一申请号的合并必须保留来源冲突记录；
- OCR 和分类结果保存置信度与模型版本；
- 删除或更正来源记录后，相关索引能够按来源追踪并重建。
