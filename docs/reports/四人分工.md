# MarkLens 四人分工与实验报告写作

本分工以“每个人都有可演示功能、可解释技术点、可写入报告的实验内容”为原则。最终报告可统一由一人排版，但每人应保留自己的截图、测试记录和负责模块说明。

| 成员 | 负责模块 | 代码范围 | 报告可写内容 | 演示任务 |
| --- | --- | --- | --- | --- |
| 成员 A：产品与前端 | 用户端、学习中心、项目创建、附件入口、品牌顾问交互、风险可视化 | `apps/web/` | 用户需求、信息架构、交互流程、响应式与可用性设计 | 新建项目 → 附件创建 → 查看图样比对 → 咨询顾问 |
| 成员 B：后端与权限 | FastAPI、认证、项目隔离、运营后台、文档导出、任务调度 | `apps/api/app/main.py`、`auth.py`、`services.py` | API 设计、角色权限、资源归属校验、异步任务与异常处理 | 普通用户/运营/管理员角色差异、报告保存与导出 |
| 成员 C：算法与数据 | 多模态检索、图样比对、OCR、数据源导入、风险规则、RAG 引用 | `retrieval.py`、`rag.py`、`attachments.py`、`sources.py` | 文本/图像/类别五维评分、OCR 归一化、真实数据边界、风险可解释性 | 展示候选图样梯度、雷达图、法律依据与不确定性 |
| 成员 D：测试与交付 | Alembic、测试、部署、Nginx、数据库、文档、GitHub 发布 | `infra/`、`scripts/`、`apps/api/tests/`、`docs/` | 测试策略、迁移、部署架构、数据安全、复现实验步骤 | 展示测试通过、服务器健康检查、运营看板和部署页面 |

## 实验报告章节建议

1. **问题与目标**（成员 A 主笔，B/C/D 补充）：传统商标初筛缺少面向非专业用户的过程解释，项目目标是把学习、整理、检索、风险解释和报告沉淀串成闭环。
2. **总体设计**（成员 A+B）：前后端分离、用户端与运营端隔离、角色模型、项目数据归属。
3. **关键技术实现**：
   - A：React 页面、附件创建流程、图样证据板、品牌顾问界面；
   - B：FastAPI 路由、JWT/刷新令牌、项目资源鉴权、异步 AgentRun；
   - C：OCR/PDF-DOCX 归一化、图文类别多模态评分、RAG 与引用校验；
   - D：MySQL 迁移、自动化测试、Nginx + systemd 部署。
4. **实验与结果**（四人各提供 1–2 张截图）：附件解析结果、图样梯度、风险雷达图、顾问引用、运营图表、健康检查和测试结果。
5. **局限与展望**（成员 C+D）：跨法域数据不等同于中国大陆权利结论、模型仅作辅助、生产环境需要合规数据许可、HTTPS 与监控。
