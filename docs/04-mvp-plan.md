# MVP 任务拆解

任务按里程碑推进。每个里程碑都应有可运行演示、测试或文档产物，不以“接上大模型”作为完成标准。

## M0：决策与数据准备

- [ ] 确认课程交付形式、运行环境、时间和团队分工；
- [ ] 确认前后端技术栈并记录 ADR-001；
- [ ] 确认首批商标与法律资料的合法来源、许可和规模；
- [ ] 定义 20–50 个演示查询及期望候选；
- [ ] 确认尼斯分类的版本与更新日期；
- [ ] 固化 MVP 文书类型为“商标注册风险评估报告”；
- [ ] 建立威胁模型：文件上传、提示注入、隐私、越权引用。

**完成标准**：数据清单、评测小集、技术决策和演示范围均有书面记录。

## M1：可追溯文本检索

- [ ] 建立商标、类别、项目和来源的迁移脚本；
- [ ] 实现数据导入校验与版本标识；
- [ ] 实现文字规范化、编辑距离/模糊匹配、拼音与文本向量召回；
- [ ] 实现候选合并、去重和类别过滤；
- [ ] 提供搜索 API 与最简结果页；
- [ ] 为每个候选展示各通道分数和来源。

**完成标准**：固定数据集上可复现 Top-K；基础相关性指标和失败样例可查看。

## M2：图像与多模态链路

- [ ] 增加图片类型、大小、像素和恶意文件校验；
- [ ] 实现图像预处理与临时文件生命周期；
- [ ] 接入可替换 OCR provider，保留置信度；
- [ ] 接入可替换图像 embedding provider；
- [ ] 合并 OCR、视觉和文本候选；
- [ ] 补充图文组合商标评测集。

**完成标准**：上传图样可返回视觉与 OCR 候选，任一 provider 不可用时可降级并明确告警。

## M3：风险提示与解释

- [ ] 定义 `[0,1]` 分数归一化和缺失值策略；
- [ ] 将权重、阈值和规则放入版本化配置；
- [ ] 输出风险等级、主要依据、反向证据和证据不足提示；
- [ ] 设计修改建议的受控规则与生成边界；
- [ ] 由领域人员抽查高/中/低样例。

**完成标准**：每个风险提示能追溯到候选和规则；界面不把分数表述为法律概率。

## M4：可信报告生成

- [ ] 设计结构化事实表单和用户确认步骤；
- [ ] 建立法律资料切分、版本和引用定位；
- [ ] 建立报告模板与必填段落；
- [ ] 实现基于证据包的分段生成；
- [ ] 实现事实字段对照、引用存在性、日期适用性和必填段落校验；
- [ ] 导出时附引用清单、告警和人工复核声明。

**完成标准**：固定样例报告无虚构事实或不存在的引用；故意注入错误时校验器能阻断导出。

## M5：演示加固与评测

- [ ] 检索指标：Recall@K、MRR/nDCG（有分级标签时）和分通道消融；
- [ ] 生成指标：事实一致率、引用有效率、必填项覆盖率和人工评分；
- [ ] 增加 provider 超时、空检索、低质量图片、冲突来源等失败场景；
- [ ] 增加审计日志、速率限制和敏感日志检查；
- [ ] 编写启动、演示、数据重建和限制说明。

**完成标准**：新环境可按文档复现演示；限制与失败模式在答辩中可说明。

## 建议的第一迭代（约一周课程节奏）

1. 完成 M0；
2. 用 50–200 条许可明确的脱敏/合成记录打通关系数据导入；
3. 只做文字规范化、模糊匹配和类别过滤；
4. 建立 20 个查询的 Recall@10 基线；
5. 做一个结果页，展示来源和分项解释；
6. 评审后再决定 embedding、OCR、向量库和工作流框架。
