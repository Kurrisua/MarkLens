# 8-10 分钟答辩演示脚本

## 演示前准备

1. 执行 `make db-up`、`make db-migrate`、`make seed`；
2. 启动 API 与 Web；
3. 准备两个浏览器账户：普通用户和 `.env` 中的演示运营账户；
4. 先完成一个普通用户项目，确保页面中已有方案、初筛、风险和报告；
5. 打开 [功能到代码索引](01-feature-map.md) 备用。

## 0:00-1:00：问题与定位

话术：

> 商标决策不是只查一个名称。用户需要理解业务、类别、图样和已有证据，还要能保留为什么作出某个选择。MarkLens 因此把学习、初筛、风险解读、报告和运营内容放进同一个受权限保护的产品流程。

展示首页的“理解 → 整理 → 初筛 → 沉淀”路径。

## 1:00-3:00：普通用户品牌项目

1. 登录普通用户，进入“我的项目”；
2. 打开项目，展示一个商标方案的名称、类别、业务描述；
3. 说明图样为可选输入，OCR 低置信度时需用户确认；
4. 点击“开始初筛”。

关键话术：

> 初筛按文字、读音、图样和类别关系形成线索，结果明确标注为教学演示数据，不把风险分数说成注册成功概率。

## 3:00-4:30：候选、风险和报告

1. 展示候选卡中的类别、原因和相似线索；
2. 进入风险解读，指出“主要关注点、可核实方向、不确定性”；
3. 生成并保存报告；再次回到风险页，展示“打开已保存报告”；
4. 在报告页编辑一段文字、保存并导出 PDF。

关键话术：

> 报告不是临时文本。它与风险分析、引用、事实快照一起保存到数据库，同一分析优先复用已有报告，避免重复生成。

## 4:30-5:30：学习闭环

1. 打开学习中心，说明每个核心专题已有 100+ 可检索学习卡；
2. 打开案例实训，完成一题并查看解析。

关键话术：

> 产品将“遇到问题”与“学习概念”连接起来，后续会由品牌顾问按项目问题推荐学习内容。

## 5:30-7:00：运营端隔离

1. 切换演示运营账户，进入运营后台；
2. 展示内容与题库编辑工作台、草稿/发布状态；
3. 展示数据源同步与最近任务；
4. 管理员展示用户角色。

关键话术：

> 用户端和运营端不是只换了菜单。API 按 `/app`、`/ops`、`/admin` 分域，并在服务端校验资源归属和角色；越权访问有自动化测试。

## 7:00-8:30：技术可信性

打开 `docs/defense/03-architecture-defense.md` 的架构图，说明：多路检索、确定性风险映射、证据约束生成、引用校验和审计。

## 8:30-10:00：未来路线

打开 `docs/14-comprehensive-optimization-roadmap.md` 的阶段表，重点说明：项目级品牌顾问、候选方案对比、品牌 DNA 卡和证据可视化。

不要说“已经实现”。推荐话术：

> 下一阶段将把已具备的 RAG 与项目事实重新接入为项目级品牌顾问，让回答可以直接触发方案比较、决策记录和报告补充。
