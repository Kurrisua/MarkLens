# MarkLens 全面项目优化路线图

> 版本：2026-07-21 · 用途：课程答辩后的功能迭代蓝图
>
> 产品定位：面向商标初学者与创业团队的“品牌决策工作台”。它帮助用户理解、比较、记录并复核品牌保护决策；不替代官方检索、行政审查或律师意见。

## 1. 总体判断

MarkLens 下一阶段不应继续堆叠彼此无关的小工具，而应围绕一条连续的用户主线升级：

```text
业务想法与品牌素材
        ↓
品牌项目与候选方案
        ↓
证据初筛与风险理解
        ↓
品牌顾问提出下一步
        ↓
方案比较、决策记录、报告与复核
```

本路线图明确**不引入语音实验室**。多模态输入优先服务图样、文字和业务材料，避免为了展示技术而增加与商标决策关联较弱的功能。

## 2. 产品能力全景

| 能力域 | 面向用户的核心价值 | 建议的代表性页面/组件 | 迭代级别 |
|---|---|---|---|
| 品牌档案 | 把名称、图样、业务背景变成可持续使用的项目事实 | 品牌 DNA 卡、候选方案版本 | P1 |
| 多模态初筛 | 理解文字、图样、OCR 与商品服务之间的近似线索 | 图样分析卡、证据地图 | P1 |
| 方案决策 | 在多个名称之间作出可解释选择 | 候选对比板、类别矩阵 | P1 |
| 品牌顾问 | 针对项目事实提出带引用、可行动的建议 | 项目级顾问空间、操作卡 | P1 |
| 决策交付 | 保存过程、生成可复用的成果物 | 决策日志、报告版本、PDF | P0-P1 |
| 学习闭环 | 用真实项目问题带动学习和练习 | 错题本、推荐学习卡 | P2 |
| 运营治理 | 维护内容、数据源、任务和质量 | 内容工作流、质量看板 | P2 |
| 可视化与动效 | 让复杂关系被看懂，而非增加装饰 | 风险雷达、类别关系图、扫描进度 | P1 |
| 可信与安全 | 确保系统结论有边界、可复核、可追溯 | 引用卡、审计、数据范围提示 | 持续 |

## 3. P0：巩固当前产品闭环

### 已有能力

- 私有品牌项目、商标方案、初筛、风险解读与可编辑报告；
- 图样上传、OCR 确认、文字/拼音/类别/图像多路检索；
- 学习中心、101 条题库与独立运营后台；
- 已保存报告复用与中文 PDF 导出；
- 用户、运营、管理员三类角色与审计基础。

### P0 收口项

1. 在项目详情增加“已有分析/报告”入口，而非只能从任务跳转进入；
2. 为报告保存版本号、最后编辑时间和“基于哪次风险分析”说明；
3. 把用户可见的任务阶段统一为业务语言，运营端保留技术阶段；
4. 在所有演示数据页面保持同一条数据边界提示；
5. 补齐关键旅程的前端渲染测试：初筛、风险、报告复用、导出。

验收：一个新用户在不理解数据库、模型或任务编号的情况下，可以完成“创建项目 → 初筛 → 风险理解 → 保存/导出报告”。

## 4. P1：品牌 DNA 与方案决策（优先级最高）

### 4.1 品牌 DNA 卡

每个候选方案生成一张“品牌画像”，汇总而不替代原始证据：

- 文字：名称、拆词、拼音、可能的近音风险；
- 图样：OCR 确认文字、主色、构图标签、视觉特征状态；
- 业务：商品服务描述、尼斯类别与待确认范围；
- 证据：本次检索的数据范围、命中数量、风险提示；
- 决策：用户是否继续、调整、搁置或排除。

图样分析只呈现“视觉近似线索”和可复核特征，不能将自动图像相似度描述为法律结论。

### 4.2 候选方案对比板

支持并排比较 2-3 个名称/图样方案，统一展示：

| 维度 | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 文字与读音线索 | 分项分数与原因 | 分项分数与原因 | 分项分数与原因 |
| 类别关联 | 当前类别与冲突点 | 当前类别与冲突点 | 当前类别与冲突点 |
| 图样线索 | OCR/视觉特征 | OCR/视觉特征 | OCR/视觉特征 |
| 建议 | 继续/调整/排除 | 继续/调整/排除 | 继续/调整/排除 |

用户可以将比较结论写入决策日志，或选定其中一项继续生成报告。

### 4.3 证据地图与类别关系图

- 证据地图：横轴为文字/读音线索，纵轴为类别接近度，气泡大小为综合相似线索；
- 类别关系图：仅展示本案类别与候选类别的交集、相邻和待核实关系；
- 所有图都可点击回到候选详情和证据来源。

验收：用户可解释“为什么方案 B 比方案 A 更值得继续”，而不是只看到一个风险等级。

## 5. P1：把法律智能体升级为项目核心

名称建议：**品牌顾问**。它不是独立聊天机器人，而是项目上下文中的决策界面。

### 5.1 顾问输入与上下文

顾问默认读取当前用户已授权的项目事实：候选名称、类别、业务描述、初筛候选、风险分析、报告草稿和已保存决策。用户不需要重复粘贴这些内容。

提供六个场景入口：

1. 解读本次初筛；
2. 比较候选方案；
3. 优化名称与类别描述；
4. 规划申请与复核步骤；
5. 解释法规与术语；
6. 为报告补充说明。

### 5.2 顾问回答标准

每次回答固定包含：**结论摘要、项目依据、法规/资料引用、不确定性、下一步操作**。回答下方可出现操作卡：

- 再次初筛；
- 创建新候选方案；
- 打开方案对比；
- 保存为决策记录；
- 插入报告；
- 跳转学习内容。

### 5.3 记忆、历史与边界

- 问答历史按项目保存，但用户可删除；
- “记忆”只保存用户主动确认的项目事实和决策，不保存模型自行推断；
- 顾问不可访问其他用户项目、原始密码、令牌和未授权数据源；
- 没有适用证据时，回答必须明确说明证据不足，不给确定性法律结论。

### 5.4 为什么现有问答消失

旧 `consultations` 逻辑仍可在服务层找到，但产品化后旧路由被退役中间件阻断，用户端也没有入口。P1 应新增 `/api/v1/app/projects/{project_id}/advisor/*`，而不是恢复旧的公开接口。

验收：用户能从项目中提问、查看引用、执行一项后续动作，并在报告中看到已保存的问答结论。

## 6. P2：学习、运营与协作增强

### 学习闭环

- 错题本与按概念归因的学习建议；
- 用户在品牌顾问中问到“显著性”“异议”等问题时，推荐相应知识卡；
- 学习进度不只统计答题次数，也统计已掌握与待巩固能力；
- 运营端显示题目正确率、易错知识点和内容覆盖率。

### 项目协作与决策记录

- 启用已有 `ProjectMembership` 预留结构，先支持只读/可编辑协作者；
- 报告段落、候选证据和决策记录可添加评论；
- 每项方案的状态：备选、继续检索、待复核、已排除、已选定；
- 决策日志可导出到报告附录。

### 运营后台

- 内容草稿、审核、发布、下架的状态流；
- 题目难度、标签、正确率与失分原因；
- 数据源最近同步、失败原因、许可信息和受控重试；
- 顾问质量抽样：无引用率、未说明不确定性率、用户追问率。

## 7. P1-P2：动效与可视化原则

动效只服务“状态变化”和“关系理解”，不做连续炫动。

| 场景 | 表现 | 用户意义 |
|---|---|---|
| 初筛任务 | 品牌指纹依次点亮文字、读音、图样、类别四层 | 解释系统正在处理什么 |
| 结果页 | 候选卡按风险线索渐进出现 | 避免一次性信息压迫 |
| 方案对比 | 雷达图/类别矩阵随方案切换更新 | 让差异可见 |
| 项目路线 | 申请与复核时间线逐步解锁 | 呈现下一步 |
| 学习进度 | 掌握度环形图与错题标签 | 指导继续学习 |

实现要求：尊重 `prefers-reduced-motion`；所有图表提供文字摘要；颜色不作为唯一风险表达方式。

## 8. 实施顺序与答辩价值

| 阶段 | 推荐交付 | 为什么值得优先展示 |
|---|---|---|
| 1 | 项目级品牌顾问 + 问答历史 + 引用 + 操作卡 | 将大模型能力接入真实任务链路 |
| 2 | 候选方案对比板 + 证据地图 | 让检索分数变得可解释、可决策 |
| 3 | 品牌 DNA 卡 + 业务材料辅助整理 | 突出多模态与项目上下文能力 |
| 4 | 决策日志 + 项目路线图 + 报告版本 | 展示完整交付闭环 |
| 5 | 错题推荐、协作、运营质量看板 | 展示长期产品运营能力 |

答辩时优先演示阶段 1-4；阶段 5 用路线图说明可扩展性。不要声称已经完成未实现的真实数据接入、自动申请或确定性法律判断。
